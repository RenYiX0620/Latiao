# 决策注释规范（半页）

> 2026-10-04 立。来源：对照 OpenAI Codex / Claude Code 的工程实践（两家都在提示词/阈值/行为改动处留「指标 + 数字 + 日期 + 归档」注释），结合本仓既有习惯（如 `compression` 里 09-19 的缓存实验注释）。

## 为什么

提示词和阈值的行为依赖上下文——半年后没人记得「为什么是 18000 而不是 8000」「为什么这条禁止要写这么重」。
**改动处的注释是唯一随代码同生共死的记忆**。没有注释的调参，下一次调整只能重新试错。

## 写什么（三件套）

1. **日期 + 一句话为什么**（必写）；
2. **依据**：实测数字 / 事故链路 / 数据盘点（有则必写，没有就写"待验证"）；
3. **临时补丁的退出条件**：这条规则是为了绕开某个模型/环境的毛病时，写明「什么情况下可以移除」。

## 实例（本仓真实注释，照这个风格写）

```python
# memory.py — 缓存自校验口径（改动原因 + 后果）
# 口径 = 活跃条数：归档是 UPDATE（不改行数），按总数比对会漏掉归档 →
# archived 条目会一直留在缓存里（2026-10-04 记忆固化时加）。

# memory.py — 偏好模式扩召回（事故依据）
# 10-04 扩召回：09-21 修劫持时把模式收得过窄——"别用表格"、"下次直接给结论"、
# "记住我用中文"这类真实偏好全都不命中（上线一个月 preferences 表只有 1 条，
# 用户抱怨"说过的话记不住"）。

# memory_consolidate.py — 引用内容判据（数据依据）
# 不含指向且较长的是文章、合同、问答等引用内容——它们 token 多，在 TF-IDF 里
# 与任意查询都容易重叠，是 hit 数百次的最大注入污染源（真库实测："不是DeepSeek
# 替你赚钱…"hit 386、"不是教你成为量化大牛…"hit 373）。

# db.py — 归档列（立项依据）
# ⑦ 记忆固化（2026-10-04）：归档标记。…立项依据（真库盘点）：637 条 learnings
# 里 285 条是噪音/误分类。
```

## 不写什么

- 复读代码：「把值赋给变量」；
- 给未来的自己打气：「这里很重要，不要删」——要写**为什么**重要（数据/事故）；
- 与代码矛盾的旧注释：改行为时**同轮改注释**（旧注释比没有更坏）。

## 临时补丁的退出条件写法

```python
# @[MODEL LAUNCH] 风格（Codex 实践）：模型换代后行为可能变，届时评估移除
# 09-07 临时：<模型/版本> 会把思考碎片当知识存库——开关思考后再评估是否需要此过滤
```
