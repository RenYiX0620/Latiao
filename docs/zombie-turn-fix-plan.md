## 修 2（最痛）：让被挂住的轮**一定**退出

根因：`agent/loop.py::_sample` 的 900s 单步超时是**按收到的行**计时的——一行都没有时永不触发；`_logged_agent_turn` 的 `finally`（负责 `end_turn`）只在生成器真正退出时才跑，所以生成器一挂，状态就永久 running。

改法（三层，各自独立有价值）：
- **2a 轮次墙钟守卫**：`LATIAO_ROUND_MAX_WALL`（默认 600s）。在 `_sample` 外起一个 watchdog task，超时则 `cancel` 本轮生成并把原因写进交付（"引擎 N 分钟无响应，已中止本轮"），让生成器**正常退出** → `finally` 跑 → `end_turn`。
  注意：**不能**用 `asyncio.wait_for(anext(agen))`（既有教训：取消 anext 会让异步生成器永久结束）；`_stream` 已是"泵 + 队列"模型，用队列超时/任务取消即可。
- **2b 静默心跳**：`_sample` 里"30s 没收到任何行"→ `yield {"event": "heartbeat"}`（前端看门狗**每收到一字节就重置**，180s 误杀因此消掉；顺带解决修 1 之外的其他静默来源）。
- **2c 状态自愈**（纯后端，热更即生效）：`loop_state.begin_turn` 拒绝新轮时，检查该会话"最后一个事件的时间"（`session_log` 或 `context_stats.turn_started_ms`/最后 step）；超过 `3×180s` → 强制结束旧轮 + 记日志 + 放行新轮，而不是把用户永久卡死。

## 修 1：思考不进语言漂移闸（4 行）

`_sample` 的 `if think:` 分支**直接 `yield {"reasoning": think}`**，只有 `content` 进 `_pending` 参与漂移判定（漂移判据本来只用 `body_text`，思考从不参与；被攒着纯属共用闸门的副作用）。
副作用（已知并接受）：被丢弃重采的尝试，其思考会先出现在屏幕上（思考是折叠的次要信息；若前端是"按步追加"需确认，必要时在重试前发一次清空思考事件）。
